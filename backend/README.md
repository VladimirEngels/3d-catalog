# Бэкенд 3D-Каталога

REST API на Node.js, TypeScript и Express. Данные хранятся в PostgreSQL,
файлы моделей и текстуры — в `storage/`.

Установка, настройка базы, запуск и демонстрационные аккаунты описаны
в [основном README](../README.md).

## Структура

| Путь | Назначение |
|---|---|
| `src/app.ts` | Настройка Express, подключение маршрутов и обработка ошибок |
| `src/server.ts` | Запуск сервера и очистка просроченных сеансов |
| `src/db.ts` | Подключение к PostgreSQL и выполнение транзакций |
| `src/modules/` | Учётные записи, команды, каталог, загрузка, задания и администрирование |
| `src/middleware/` | Проверка сеанса, прав доступа и журналирование запросов |
| `src/storage.ts` | Работа с файловым хранилищем |
| `schema.sql` | Схема базы данных |

В модулях `routes.ts` обрабатывает HTTP-запросы, `repository.ts` содержит
SQL-запросы. Для отдельных сценариев правила вынесены в `service.ts`.

## Авторизация и доступ

Пароли хешируются с помощью scrypt и индивидуальной соли. Сеанс передаётся
в cookie с параметрами `HttpOnly`, `Secure` и `SameSite=Lax`; в базе хранится
SHA-256-отпечаток токена. Права проверяются сервером при каждом защищённом запросе.

Доступ к моделям определяется членством и ролью в команде. Права системного
администратора сами по себе не дают доступа к содержимому моделей команд.

Для назначения администратора зарегистрируйте пользователя и выполните из корня репозитория:

```powershell
npm --prefix backend run make-admin -- user@example.com
```

Для снятия прав:

```powershell
npm --prefix backend run make-admin -- user@example.com --remove
```

## Загрузка моделей

Поддерживаются OBJ, STL, PLY, glTF и GLB, включая загрузку в ZIP-архивах.
Максимальный размер загружаемого файла — 100 МБ. При загрузке вычисляются
характеристики модели и контрольная сумма для поиска дубликатов.
Браузер создаёт превью через Three.js.

Сведения о моделях и версиях хранятся в PostgreSQL, файлы — в `storage/`.
Базу и файловое хранилище следует резервировать вместе.

## Журналирование

Сервер пишет события и сведения о запросах в терминал и `logs/<дата>.log`.
Используются уровни `INFO`, `WARN` и `ERROR`.
Журнал действий команды хранится отдельно в таблице `action_log`.

## Ограничения

- Конвертер, автоматическая проверка качества и нейросеть не подключены; новые задания остаются в очереди.
- В демонстрационной базе часть результатов и отчётов подготовлена заранее.
- Нет ограничения числа попыток входа, подтверждения почты и отправки приглашений по электронной почте.
- Приглашения доступны через интерфейс и ссылки.
- Сервер слушает только `localhost`; для сетевого размещения нужны отдельная настройка доступа и HTTPS.
